# Task 1：从 C 源码到可执行文件

请用自己的语言简要说明下面几个阶段分别做了什么：

1. 预处理

- 头文件展开`#include<stdio.h>`
  
  把`stdio.h`等头文件里的全部内容都复制粘贴到hello.i里面
- 宏替换`#define`

  把代码中所有宏名字替换成宏定义中的对应文本，比如`#define n 10`就把所有n换成10
- 删除注释

  把`// ``/* */`全部删掉
- 处理条件编译`#ifdef/#else/#endif`

  根据宏是否定义，保留或者删除一部分代码。
  
此时不会处理语法错误

2. 编译

- 检查语法错误
  
- 词法分析、语法分析、语义分析
  
- 将c语句翻译成汇编指令

  C 语言是高层抽象，汇编是 CPU 指令集，CPU 只认识汇编指令，比如：`mov` 数据搬运、`push`栈压入。代码里的`printf("Hello, World!\n");`会变成汇编里调用`printf`函数的指令。

3. 汇编

汇编器把.s里面的文本形式的汇编指令翻译成CPU可以直接识别的二进制机器码，方便运行。

但是虽然CPU已经可以识别，hello.o还不能直接运行，原因：
- .o还没有确定代码地址，`.o`内部所有跳转、函数调用、全局变量引用，全部使用临时、未确定的偏移量，不是真实虚拟内存地址

- 外部函数还没有地址，虽然汇编里调用`printf`函数，但是`printf`函数实现不在hello.o里面，只有一个符号占位标记，并没有找到库的实现

- 文件格式是ELF目标文件，不是完整可执行ELF程序

4. 链接

- 符号解析
  此时链接器去系统c标准库`shturl.`里面找到`printf`函数的真实机器码实现，把上一步的占位符换成真实的函数地址，如果此时找不到函数实现就会报错`undefined reference to 'xxx'`，这是链接报错，和编译报错不同
- 重定位
  修正所有代码地址，确定真实虚拟内存地址，拼接整合所有机器码生成可执行ELF程序，此时可以`./hello`运行

建议控制在 300～500 字，不需要展开复杂细节。
